## 1. The headline: zero of the fifteen vehicle-in-water simulations reach the reference list

The submitted paper is `conference_101719_1.tex` at the root of the `overleaf` remote, branch
`main`, together with `can_it_ford_references_IEEE.bib` beside it. Read directly, at local ref
`6466dfa` (2026-07-31; the local ref is 18 days stale, so re-check before acting):

```

distinct \cite keys in the tex           14
cite keys with no bib entry               0     (nothing compiles to [?])
bib entries never cited                   1     xiong2024
\nocite anywhere in the tex               0
line 265  \bibliographystyle{IEEEtran}
line 266  \bibliography{can_it_ford_references_IEEE}
```

The absence of `\nocite` is the load-bearing part. With `\bibliographystyle{IEEEtran}` and a
plain `\bibliography{...}`, BibTeX emits only the entries that were cited. An uncited entry is
therefore not a reference the reader ever sees. This was checked three ways that do not share a
mechanism: a Python `re` walk over `\cite{...}` groups, a shell loop doing `grep -c -F` per bib
key, and a `grep -o | tr | sort -u | wc -l` count of distinct keys. All three give 15 entries,
14 keys, and `xiong2024` as the single uncited entry.

Now cross that against D1's cross-referenced table of vehicle-in-water simulations
(`claude/r5-research:docs/R5_RESEARCH_ELICIT_AND_CATALOG_MINE_2026-08-16.md`, the fifteen-row
table above its line 271). Testing each of those fifteen DOIs against the shipped bibliography:

```
DOIs with a bib entry in the shipped bibliography     1 of 15   (10.1029/2023WR036739)
of those, cited in the tex                            0 of 1
```

`10.1029/2023WR036739` is `xiong2024`, and `xiong2024` is exactly the one entry nothing cites.

**So zero of the fifteen appear in the paper's reference list.** Not one is cited, and the single

### Qualification, which I found by attacking my own headline. Read this before quoting it.

"Zero of D1's fifteen reach the reference list" is true. **"The paper cites no prior
particle-method simulation of a vehicle in floodwater" would be false**, and the sentence above
must not be paraphrased into it.

The paper cites `azhar2023`, `10.1111/jfr3.12885`, "Confirmation of vehicle stability criteria

So the accurate statement of the gap is narrower than the headline sounds, and it is this: the

## 2. The root error, and why two instances in one night is a finding about method

Both failures reduce to one substitution: **a bibliography entry was counted as a citation.**

**Instance 1, the project's own novelty gate.** `.claude/tooling/corpus_mcp.py:211-228`,
`corpus_cited_status`, read directly. Its docstring names its purpose: "THIS IS THE NOVELTY
GUARD. On 2026-08-14 four vehicle-fording papers ... sat in our own catalogs uncited while the
project prepared to claim nobody had simulated fording." The implementation is:

```python

       REPO + "/paper", REPO + "/CLAUDE.md"]
...
"cited_in_repo": len(repo_hits) > 0,
"verdict": ("IN CORPUS BUT NOT CITED, investigate"
            if corpus["files"] and not repo_hits else
            "cited" if repo_hits else "not found either place")
```

Reproduced live, all four DOIs now return hits:

| DOI | hits |
|---|---|
| `10.1115/1.4071177` | 4 files in `docs/`, `paper/can_it_ford_references_IEEE.bib`, `CLAUDE.md` |
| `10.1115/DETC2015-47142` | 2 files in `docs/`, the bib, `CLAUDE.md` |
| `10.4271/2014-01-0936` | 2 files in `docs/`, the bib, `CLAUDE.md` |
| `10.1111/jfr3.12828` | 3 files in `docs/`, the bib, `CLAUDE.md` |

Zero hits in any `.tex`, in any of the four cases. The gate now answers `"cited"` for precisely
the four papers it exists to catch, and it does so because the sessions that discovered the gap
wrote the DOIs into `docs/`, into the bib, and into `CLAUDE.md`. The act of recording the
problem is what silenced the alarm.

Three separate defects, all from the source read:

1. It searches `docs/`, which holds drafts, audits, session notes and research plans. A DOI
   named in a research plan is not a citation in a paper.
2. It searches `paper/*.bib` and treats a hit there as "cited". An uncited bib entry does not
   appear in an IEEEtran reference list, as Section 1 shows with a live example.
3. It never reads the canonical paper source at all. `conference_101719_1.tex` lives on the
   `overleaf` remote and is not in the working tree, so the one file that could answer the
   question is the one file the tool does not open.

**Instance 2** is D1's "two reach the paper" in Section 1 above, from the same substitution
applied by hand.

The two are independent in origin: one is a Python function in `.claude/tooling/`, the other is
a manual classification in a research document on a different branch, written by a different
session. They are not two reports of one event. That is what makes this a finding about method
rather than about two numbers: the test "does this string appear in the repository" was
substituted for the test "does this work appear in the paper's reference list", twice, by
different routes, on the same night.

**The general rule this implies.** For any citedness claim about this project, name which of
four states you mean, because they are not the same and three of them print nothing:

```
mentioned      the string appears somewhere in the repository
in bibliography  a @entry exists in a .bib file
cited            a \cite{key} appears in the canonical paper source
in the reference list   cited AND the bib entry resolves, so IEEEtran prints it
```

## 3. Ready-to-apply fix for the novelty gate

`.claude/tooling/corpus_mcp.py` is **not in this slot's write scope**, it is untracked, it lives
in the main checkout, and slot `d6-tooling` is live on `claude/r8-tooling`. I have not edited it.
What follows is for `d6-tooling` to verify independently and apply.

The logic below was extracted and run standalone this session against the live repository, so
the behaviour claims are measured, not predicted. It has **not** been run inside the MCP server
process, because restarting that server would affect every other live session.

Replace the body of `corpus_cited_status` with:

```python
def corpus_cited_status(needle):
    # Four distinct states, because three of them print nothing in the paper.
    # A bibliography entry is NOT a citation: an uncited @entry never reaches an
    # IEEEtran reference list. Measured 2026-08-18: xiong2024 is in the shipped
    # bibliography, is cited nowhere, and therefore does not appear in the paper.
    # /usr/bin/grep, never the shell function: the shell grep is a ugrep wrapper
    # with --ignore-files and silently skips gitignored paths.
    def _grep(paths):
        try:
            r = subprocess.run(["/usr/bin/grep", "-rIl", "--", needle] + paths,
                               capture_output=True, text=True, timeout=60)
            return [x for x in r.stdout.splitlines() if x.strip()]
        except Exception as e:
            return ["<grep failed: %s>" % e]

    # 1. loose mention: drafts, notes, standing rules. Says nothing about the paper.
    mentioned = _grep([REPO + "/docs", REPO + "/CLAUDE.md"])

    # 2. bibliography entry, in any .bib under paper/.
    bib_hits = _grep([REPO + "/paper"])
    bib_hits = [p for p in bib_hits if p.endswith(".bib")]

    # 3. the canonical paper source is on the overleaf remote, not in the tree.
    #    Resolve the needle to bib keys first, then look for \cite{key}.
    paper_src, paper_err, bib_src = "", None, ""
    for ref, path in (("overleaf/main", "conference_101719_1.tex"),):
        try:
            paper_src = subprocess.run(
                ["git", "-C", REPO, "show", "%s:%s" % (ref, path)],
                capture_output=True, text=True, timeout=60).stdout
            bib_src = subprocess.run(
                ["git", "-C", REPO, "show",
                 "%s:can_it_ford_references_IEEE.bib" % ref],
                capture_output=True, text=True, timeout=60).stdout
        except Exception as e:
            paper_err = str(e)

    keys = []
    if bib_src:
        for m in re.finditer(r'@(\w+)\s*\{\s*([^,\s]+)\s*,', bib_src):
            start = m.start()
            end = bib_src.find("\n@", start + 1)
            body = bib_src[start:end if end > 0 else len(bib_src)]
            if needle.lower() in body.lower():
                keys.append(m.group(2))

    cited_keys = set()
    if paper_src:
        for m in re.finditer(r'\\cite\{([^}]*)\}', paper_src):
            for k in m.group(1).split(","):
                if k.strip():
                    cited_keys.add(k.strip())
    nocite = bool(paper_src) and "\\nocite" in paper_src

    in_paper = sorted(set(keys) & cited_keys)
    in_bib_only = sorted(set(keys) - cited_keys)
    corpus = corpus_search(needle, max_files=10)

    if in_paper:
        verdict = "CITED IN THE PAPER, keys: " + ", ".join(in_paper)
    elif in_bib_only:
        verdict = ("IN THE BIBLIOGRAPHY BUT NEVER CITED, so it does NOT appear in the "
                   "reference list. Keys: " + ", ".join(in_bib_only))
    elif bib_hits:
        verdict = ("IN A REPO .bib BUT NOT IN THE SHIPPED BIBLIOGRAPHY, "
                   "so it cannot reach the paper")
    elif corpus["files"]:
        verdict = "IN CORPUS BUT NOT CITED, investigate"
    elif mentioned:
        verdict = "MENTIONED IN NOTES ONLY, not cited"
    else:
        verdict = "not found either place"

    return {"needle": needle,
            "cited_in_paper": bool(in_paper),
            "paper_cite_keys": in_paper,
            "in_bibliography_uncited": in_bib_only,
            "in_repo_bib_files": bib_hits,
            "mentioned_in_notes": mentioned,
            "present_in_corpus": len(corpus["files"]) > 0,
            "corpus_files": [f["path"] for f in corpus["files"]],
            "paper_source_read": bool(paper_src),
            "paper_source_error": paper_err,
            "nocite_present": nocite,
            "warning": ("The local overleaf/main ref can be stale; "
                        "run `git -C %s fetch overleaf` before trusting a NOT CITED "
                        "verdict." % REPO),
            "verdict": verdict}
```

- Keeping `mentioned_in_notes` as a separate field, rather than dropping the `docs/` search, is
  deliberate. The information is useful, it just must not be called "cited".

## 5. Bibliography audit: title against resolved record

**Method.** Scholar Sidekick `auditBibliography` in two batched calls plus one `verifyCitation`,
each entry checked as claimed-title against the record its identifier actually resolves to, plus
a retraction lookup. This catches the dominant fabrication pattern, a real resolvable identifier
paired with an invented title, which following the link does not catch. Titles were taken
verbatim from the `.bib` files, not retyped.

**Result: 18 distinct works audited, 16 matched, 2 mismatched, 0 not found, 0 ambiguous, 0
retracted, 1 carrying a correction notice.** Both mismatches named below.

### Mismatch 1: `hsiaokumar2025`, an invented title on a real identifier

This is in **this branch's** bibliography, `paper/can_it_ford_references_IEEE.bib`.

```
claimed  (repo bib)  NeRF-to-MPM Inversion for Granular Material Property Estimation
resolved (arXiv 2507.09005 via DataCite)
                     From images to properties: a NeRF-driven framework for
                     granular material parameter inversion
similarity 0.713, verdict mismatch
```

The identifier is real and resolves. The title does not correspond to it. This is exactly the
Topaz pattern. It matters more than usual here because the work is Hsiao and Kumar, and Kumar
is the PI.

The resolved record also shows the work is **published**, not a preprint: EPJ Web of
Conferences vol 340, p 10017, `10.1051/epjconf/202534010017`. The Overleaf bibliography has the
title right but cites it as "arXiv preprint arXiv:2507.09005". So the two bibliographies are
each wrong about a different half of the same entry, and neither is correct on its own.
`claude/add-ci-checks` has already fixed both halves; its entry carries the EPJ venue, the DOI,
the arXiv eprint, and a note recording the live verification.
