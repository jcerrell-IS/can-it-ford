Do not quote 92, 94 or 97 without saying which you counted. Re-run:

```bash
git for-each-ref --format='%(refname:short)' refs/remotes/origin | wc -l
git branch -r --merged origin/main
```

## The classification, and what it means

| class | count | meaning |
|---|---|---|
| **superseded** | **39** | the branch tip is already contained in at least one other remote branch, so deleting the ref loses no commit |
| **unique** | **53** | carries commits contained in no other branch. Deleting one of these DOES lose work |

The test is containment, not date and not name. A branch is called superseded here only because
`git branch -r --contains <tip>` named another branch holding the same tip.

## The 53 unique branches are the real question

Each holds work that exists nowhere else on the remote. That is 53 branches of deliverables that
never reached `main`, which matches the R9 loop-closure finding that 13 branches held
deliverables and 0 had landed. **Deleting any of these loses work.** They need reading before
they need tidying, and that is a separate job from branch hygiene.

The full list with dates and ahead-counts is in the TSV. Sorted by date, the oldest unique
branches are from 2026-07-23 and the newest from 2026-08-25.

## What not to do

Do not delete a branch because it looks stale by name or date. `origin/vista-realism-track-2026-08-13`
looks old, and Vista's own clone is 14 commits ahead on its `main` with 64 dirty files, so the
cluster state and the remote branch state are not the same thing and neither is a proxy for the
other.
